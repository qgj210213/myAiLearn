# 周6：工程化部署（Docker、简单 API、监控）

重点学习：把模型包装成服务、容器化、简单部署与监控、日志与健康检查。

必学要点：
- 先建立“能跑起来还不够，还要能稳定交付”的工程意识：服务、容器、日志、监控要串起来。
- 掌握模型服务化的基本路径：本地脚本 -> API -> Docker 镜像 -> 可部署服务。
- 能看懂并处理最常见的线上问题：服务启动失败、依赖缺失、接口超时、日志排查困难。

必做小项目（3–7 天）：
- 相关项目：部署演示、RAG 问答系统（详见 PROJECTS.md，关联周：Week1, Week6, Week8）

工作要点：
- 能解释部署流程与常见故障排查
- 熟悉 Docker 命令与容器化注意点

## 周6 详细要学习内容（表格）

| 主题 | 详细要学习的内容 | 必须掌握 | 进阶 / 备注 |
|---|---|---:|---|
| 服务化基础 | API 服务、请求响应、接口设计、错误码 | 能把模型脚本封装成 HTTP 服务 | gRPC 可后学 |
| FastAPI 部署 | 路由、参数校验、Uvicorn、返回结构统一 | 能写出可直接调用的推理接口 | 中间件和依赖注入可进阶 |
| Docker 基础 | Dockerfile、build、run、port、volume、env | 能构建并运行服务镜像 | 多阶段构建属于进阶 |
| 依赖与配置 | requirements、环境变量、配置文件管理 | 能让项目在新机器上复现运行 | 配置中心属于进阶 |
| 日志与监控 | access log、error log、健康检查、基础指标 | 能看日志定位常见问题 | Prometheus/Grafana 可进阶 |
| 性能基础 | 并发、超时、资源限制、响应时间 | 知道接口为什么会慢 | 压测与优化可后补 |
| 故障排查 | 启动失败、端口冲突、依赖错误、内存不足 | 能定位并修复基本部署问题 | 灰度发布、回滚属于进阶 |

---

## 每日/每项练习建议
- Day 1：把一个本地推理脚本改成 FastAPI 接口。
- Day 2：补上输入校验、错误返回和健康检查接口。
- Day 3：写 Dockerfile，构建镜像并本地运行。
- Day 4：增加日志输出，记录请求耗时和错误信息。
- Day 5：模拟一个错误场景，练习通过日志和接口状态排查问题。

速学资源（选一）： Docker 官方教程、FastAPI 部署指南

小贴士：先保证“本地能稳定跑”，再考虑镜像优化和更复杂的部署方式。
