# 周5：RAG + 向量数据库（FAISS/Milvus 基本用法）

重点学习：向量化文本、向量搜索原理、构建 RAG 流水线、部署向量 DB、连接检索与生成。

必学要点：
- 先理解 RAG 的核心目标：不是让模型“凭空回答”，而是先找资料再生成答案。
- 掌握从文本到向量再到检索结果的完整链路，知道向量库在里面起什么作用。
- 能独立搭一个最小可用的 RAG 流程：切分文档、生成向量、检索上下文、调用模型回答。

必做小项目（3–7 天）：
- 相关项目：RAG 问答系统、Multi-step Agent（详见 PROJECTS.md，关联周：Week4, Week5, Week7）

工作要点：
- 能解释向量检索流程与召回/精确率权衡
- 熟悉向量库基本 API

## 周5 详细要学习内容（表格）

| 主题 | 详细要学习的内容 | 必须掌握 | 进阶 / 备注 |
|---|---|---:|---|
| RAG 基础 | 检索增强生成的整体流程、为什么要做检索 | 能说清 RAG 各模块职责 | 高级 rerank 可后学 |
| 文档处理 | 文档清洗、切分 chunk、chunk 大小与 overlap | 能把原始文档切成适合检索的片段 | 复杂文档解析属于进阶 |
| Embedding | 文本向量化、embedding 模型选择、向量维度 | 能生成文本向量并理解向量相似度 | 多语 embedding 可进阶 |
| 向量数据库 | FAISS/Milvus 的索引、插入、查询、删除 | 能完成最基本的 CRUD 和检索 | 分布式向量库可后补 |
| 检索策略 | top-k、相似度阈值、召回与精度平衡 | 能调出一个基本可用的搜索效果 | rerank、hybrid search 可进阶 |
| 生成阶段 | 把检索结果拼进 prompt，控制上下文长度 | 能让模型基于上下文回答 | 上下文压缩可进阶 |
| 评估与排错 | 检索错、生成错、chunk 不合理、embedding 不匹配 | 能分辨问题出在检索还是生成 | 自动评估体系可后补 |

---

## 每日/每项练习建议
- Day 1：选一份小文档集，完成清洗和 chunk 切分。
- Day 2：生成 embedding，并把数据写入 FAISS 或 Milvus。
- Day 3：做检索接口，观察不同 top-k 和 chunk 大小的效果。
- Day 4：把检索结果拼接进 prompt，完成一个最小 RAG 问答流程。
- Day 5：针对错答案例做分析，调整 chunk、检索条数或 prompt。
