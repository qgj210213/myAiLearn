# 周8：项目打磨 + 算法/系统面试题复习

重点学习：项目完善、性能优化、面试题复习（系统设计、算法基础、模型工程问题）。

必学要点：
- 最后一周重点不是再学很多新东西，而是把前面做过的内容整理成能展示、能复现、能解释的成果。
- 重点提升“交付感”：项目结构清晰、README 清楚、Demo 可跑、问题能定位、方案能解释。
- 学会从工作视角复盘项目：为什么这样选型、哪里做过权衡、出了问题怎么排查和优化。

必做小项目（3–7 天）：
- 可选项目：RAG、Multi-step Agent、部署演示（详见 PROJECTS.md），建议用于项目打磨与展示

工作要点：
- 能解释模型选择、评价指标与工程权衡
- 熟悉常用库并能现场写推理/接口代码
- 能讲清项目架构与故障排查流程

## 周8 详细要学习内容（表格）

| 主题 | 详细要学习的内容 | 必须掌握 | 进阶 / 备注 |
|---|---|---:|---|
| 项目打磨 | README、目录结构、依赖说明、运行步骤 | 能让别人按文档跑起来 | 自动化脚本可进阶 |
| Demo 展示 | API 演示、截图、日志示例、失败案例说明 | 能在短时间内清楚展示项目价值 | 演示网站可后补 |
| 性能与成本 | 延迟、吞吐、并发、模型调用成本 | 能指出当前项目的主要优化点 | 深入压测可进阶 |
| 架构表达 | 数据流、模块边界、依赖关系、扩展点 | 能把系统讲清楚 | 架构图工具可辅助 |
| 故障排查 | 常见报错、检索失败、输出不稳定、部署异常 | 能从日志和现象反推问题 | 系统化告警可进阶 |
| 复盘与总结 | 方案选择、踩坑记录、后续优化计划 | 能清楚讲项目中的判断过程 | 形成技术博客属于进阶 |
| 求职准备 | 项目亮点提炼、简历描述、常见追问准备 | 能把项目讲成工作能力证明 | 模拟面试可后补 |

---

## 每日/每项练习建议
- Day 1：统一整理项目目录、依赖和 README。
- Day 2：补一份完整 Demo 流程，保证别人能快速看到效果。
- Day 3：列出项目里的 3 个关键技术选择，并写出原因。
- Day 4：整理常见错误和排查思路，形成自己的故障清单。
- Day 5：用 2 到 3 分钟口述一次项目，检查表达是否清晰。
